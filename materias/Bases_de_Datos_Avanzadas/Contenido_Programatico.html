🎯 PROPÓSITO GENERAL ​

Capacitar al futuro Ingeniero en Informática en el diseño, implementación y optimización de arquitecturas de bases de datos avanzadas, dominando paradigmas objeto-relacionales, bases de datos activas (disparadores y procedimientos en el servidor), vistas materializadas, consultas analíticas de alto rendimiento y técnicas de indexación física para soportar aplicaciones empresariales a gran escala y proyectos sociotecnológicos de envergadura nacional.

🔌 SABERES Y CONTENIDO ANALÍTICO ​

Unidad 1: Metodologías de Diseño Conceptual Avanzado y Calidad de Esquemas ​

  • Modelado Conceptual en Ingeniería:
    • Abstracciones de datos: Agregación, Clasificación, Generalización y Asociación.
    • Análisis del Universo del Discurso en sistemas corporativos complejos.
  • Métricas de Calidad de Esquemas de Bases de Datos:
    • Completitud, minimalidad, expresividad y legibilidad.
    • Trade-offs de diseño: Normalización extrema vs. Desnormalización controlada para lectura masiva (OLAP / Data Marts básicos).

Unidad 2: Paradigmas de Bases de Datos y el Modelo Objeto-Relacional ​

  • Evolución Más Allá de las Tablas Planas:
    • Limitaciones del modelo relacional puro ante estructuras no tabulares (impedancia objeto-relacional).
    • Paradigmas: Bases de Datos Orientadas a Objetos (OODBMS) vs. Sistemas Objeto-Relacionales (ORDBMS).
  • El Motor Objeto-Relacional en PostgreSQL:
    • Tipos de datos compuestos y tipos definidos por el usuario (CREATE TYPE AS ENUM / OBJECT).
    • Herencia de tablas (INHERITS).
    • Almacenamiento semiestructurado: columnas JSON y JSONB indexables, operadores de extracción (->, ->>, @>).
    • Comparativa de integración: Cuándo usar relacional estricto y cuándo documentos JSON embebidos.

Unidad 3: Bases de Datos Activas: Triggers y Lógica en el Servidor (PL/pgSQL) ​

  • Concepto de Base de Datos Activa:
    • Paradigma Evento-Condición-Acción (ECA - Event-Condition-Action).
    • Diferencia arquitectónica entre lógica en el Backend (Node.js/Python) vs. lógica transaccional en el motor de base de datos.
  • Funciones y Procedimientos Almacenados:
    • Estructura del lenguaje procedimental PL/pgSQL.
    • Variables, estructuras condicionales (IF-ELSE), bucles (LOOP, FOR) y manejo de excepciones.
  • Disparadores (Triggers):
    • Momentos de disparo: BEFORE, AFTER, INSTEAD OF.
    • Granularidad: FOR EACH ROW vs. FOR EACH STATEMENT.
    • Variables de contexto: NEW y OLD.
    • Casos prácticos de uso: Auditoría automática de cambios (log de operaciones), cálculo de saldos y consistencia de reglas de negocio inviolables.

Unidad 4: Consultas SQL Avanzadas, Vistas y Métricas Analíticas ​

  • Subconsultas de Alta Complejidad:
    • Subconsultas escalares, subconsultas en la cláusula FROM (tablas derivadas).
    • Subconsultas correlacionadas y operadores EXISTS, NOT EXISTS, ALL, ANY.
  • Expresiones de Tabla Comunes (CTEs - Cláusula WITH):
    • Modularización y legibilidad de consultas complejas.
    • CTEs recursivas para estructuras jerárquicas (árboles de categorías, organigramas).
  • Vistas Estándar y Vistas Materializadas:
    • Creación y actualización de vistas (CREATE VIEW).
    • Vistas Materializadas (CREATE MATERIALIZED VIEW): persistencia física de resultados para reportes ultrarrápidos y estrategias de refresco (REFRESH MATERIALIZED VIEW CONCURRENTLY).
  • Introducción a Funciones de Ventana (Window Functions):
    • Cláusula OVER (PARTITION BY ... ORDER BY ...).
    • Funciones de ranking y analítica: ROW_NUMBER(), RANK(), DENSE_RANK(), LAG(), LEAD().

Unidad 5: Optimización Física, Índices y Planes de Ejecución ​

  • El Optimizador de Consultas:
    • Cómo el motor convierte SQL declarativo en un plan físico de acceso a disco.
    • Interpretación de planes de ejecución mediante EXPLAIN y EXPLAIN ANALYZE.
    • Tipos de escaneo: Sequential Scan, Index Scan, Bitmap Index Scan.
    • Métodos de unión física: Nested Loop, Hash Join, Merge Join.
  • Estrategias de Indexación:
    • Índices B-Tree (árboles balanceados estándar para igualdades y rangos).
    • Índices GIN (Generalized Inverted Index) para búsquedas de texto completo (Full-Text Search) y documentos JSONB.
    • Índices parciales (CREATE INDEX ... WHERE condicion) e índices compuestos.
    • Costo de los índices: Mantenimiento en operaciones de escritura (INSERT/UPDATE).

🛠️ ESTRATEGIAS METODOLÓGICAS ​

  1. Talleres de Ingeniería y Rendimiento: Laboratorios donde el estudiante debe optimizar consultas que procesan cientos de miles de registros simulados, reduciendo los tiempos de ejecución de segundos a milisegundos.
  2. Desarrollo de Triggers de Auditoría para el Proyecto Sociotecnológico III (PST-III): Implementación de sistemas de registro de trazas y seguridad que certifiquen quién, cuándo y qué modificó en la base de datos comunitaria.
  3. Benchmarking Comparativo: Pruebas controladas comparando rendimiento de vistas estándar vs. vistas materializadas indexadas.
