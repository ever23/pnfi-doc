🧭 Introducción: La Superación de la Impedancia Objeto-Relacional ​

En Trayecto II aprendimos las leyes sagradas del modelo relacional clásico: cada celda debe contener un valor estrictamente atómico (Primera Forma Normal). Sin embargo, en la ingeniería moderna nos enfrentamos cotidianamente a la Disonancia o Impedancia de Objeto-Relacional: los lenguajes de programación modernos (JavaScript/TypeScript, Python, Java) operan con objetos dinámicos anidados, diccionarios y arrays; mientras que las bases de datos relacionales puras obligan a trocear esos objetos en decenas de tablas planas interconectadas con claves foráneas.

Para cerrar esta brecha nacen los Sistemas Gestores de Bases de Datos Objeto-Relacionales (ORDBMS), de los cuales PostgreSQL es el referente de código abierto más avanzado del mundo.

En esta lectura dominarás:

  1. Cómo extender el motor con tipos de datos definidos por el usuario (CREATE TYPE).
  2. El uso de la herencia de tablas (INHERITS).
  3. El poder del tipo JSONB indexable para combinar lo mejor del mundo relacional con la flexibilidad de NoSQL.

🧱 CAPÍTULO I: Tipos Definidos por el Usuario (UDTs) y Enumeraciones ​

En lugar de limitarnos a enteros y cadenas, en PostgreSQL podemos definir nuestros propios tipos de datos semánticos a nivel de esquema:

1. Tipos Enumerados (ENUM) ​

Garantizan que una columna solo acepte un conjunto cerrado de valores predefinidos sin necesidad de crear una tabla catálogo externa:

sql
-- Definición del tipo enumerado para estados de proyectos
CREATE TYPE estado_proyecto AS ENUM (
    'PROPUESTA',
    'EN_DESARROLLO',
    'EN_REVISION',
    'APROBADO',
    'RECHAZADO'
);

CREATE TABLE proyectos (
    id SERIAL PRIMARY KEY,
    titulo VARCHAR(200) NOT NULL,
    comunidad VARCHAR(150) NOT NULL,
    estado estado_proyecto NOT NULL DEFAULT 'PROPUESTA'
);

2. Tipos de Datos Compuestos ​

Permiten empaquetar múltiples atributos relacionados en una sola unidad lógica:

sql
-- Definición de una coordenada geográfica personalizada
CREATE TYPE punto_geografico AS (
    latitud NUMERIC(9, 6),
    longitud NUMERIC(9, 6),
    altitud_msnm NUMERIC(6, 2)
);

CREATE TABLE sedes_comunitarias (
    id SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    ubicacion punto_geografico NOT NULL
);

-- Inserción utilizando constructor de tipo
INSERT INTO sedes_comunitarias (nombre, ubicacion)
VALUES ('Ambulatorio Central Valera', ROW(9.317542, -70.603333, 540.00));

-- Consulta accediendo a los campos internos del tipo compuesto
SELECT nombre, (ubicacion).latitud, (ubicacion).longitud 
FROM sedes_comunitarias;

🧬 CAPÍTULO II: Herencia de Tablas en PostgreSQL ​

PostgreSQL implementa herencia nativa de esquemas basada en la programación orientada a objetos. Una tabla hija hereda automáticamente todas las columnas y restricciones de la tabla padre:

sql
-- Tabla Padre: PERSONAS
CREATE TABLE personas (
    id SERIAL PRIMARY KEY,
    cedula VARCHAR(15) NOT NULL UNIQUE,
    nombres VARCHAR(100) NOT NULL,
    apellidos VARCHAR(100) NOT NULL,
    fecha_nacimiento DATE NOT NULL
);

-- Tabla Hija 1: MEDICOS (hereda todo de personas)
CREATE TABLE medicos (
    matricula_sanitaria VARCHAR(30) NOT NULL UNIQUE,
    especialidad VARCHAR(100) NOT NULL
) INHERITS (personas);

-- Tabla Hija 2: PACIENTES (hereda todo de personas)
CREATE TABLE pacientes (
    historia_clinica VARCHAR(20) NOT NULL UNIQUE,
    grupo_sanguineo VARCHAR(5) NOT NULL
) INHERITS (personas);

Comportamiento Polimórfico en Consultas: ​

  • Si consultas la tabla padre: SELECT * FROM personas;
    PostgreSQL devuelve automáticamente tanto las personas base como los médicos y los pacientes.
  • Si solo deseas las filas de la tabla padre pura:
    SELECT * FROM ONLY personas;

📦 CAPÍTULO III: Almacenamiento Semiestructurado con JSONB ​

Una de las capacidades más revolucionarias de PostgreSQL es su soporte de primera clase para documentos JSON.

Diferencia entre JSON y JSONB: ​

  • JSON (Texto plano): Almacena una copia exacta del texto JSON con espacios. Es más rápido de insertar, pero más lento de consultar y no soporta índices.
  • JSONB (Binary JSON): Almacena el JSON descompuesto en un formato binario optimizado. Elimina espacios en blanco y claves duplicadas, permite búsqueda instantánea mediante operadores especializados y soporta indexación GIN.
sql
CREATE TABLE historias_medicas (
    id SERIAL PRIMARY KEY,
    paciente_cedula VARCHAR(15) NOT NULL,
    fecha_registro TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    -- Columna semiestructurada para datos dinámicos y signos vitales
    parametros_clinicos JSONB NOT NULL
);

Inserción de Datos JSONB: ​

sql
INSERT INTO historias_medicas (paciente_cedula, parametros_clinicos)
VALUES (
    'V-18999888',
    '{
        "presion_arterial": {"sistolica": 120, "diastolica": 80},
        "temperatura_c": 36.8,
        "alergias": ["Penicilina", "Ibuprofeno"],
        "observaciones_doctor": "Paciente hemodinámicamente estable"
    }'::jsonb
);

Operadores de Consulta JSONB: ​

OperadorSignificadoTipo de RetornoEjemplo
->Extrae campo o elemento por claveJSONBparametros_clinicos -> 'presion_arterial'
->>Extrae campo como texto planoTEXTparametros_clinicos ->> 'temperatura_c'
#>Extrae ruta anidadaJSONBparametros_clinicos #> '{presion_arterial, sistolica}'
@>Comprueba contención (Si el JSON contiene al otro)BOOLEANparametros_clinicos @> '{"alergias": ["Penicilina"]}'
sql
-- Consulta: Pacientes con presión sistólica mayor a 130 (Hipertensos)
SELECT 
    paciente_cedula,
    (parametros_clinicos #>> '{presion_arterial, sistolica}')::INT AS sistolica
FROM historias_medicas
WHERE (parametros_clinicos #>> '{presion_arterial, sistolica}')::INT > 130;

🎯 Criterio de Ingeniería: ¿Cuándo Usar Tablas Relacionales vs. Columnas JSONB? ​

  • Usa Tablas Relacionales Normalizadas cuando:
    Los datos son de esquema rígido, altamente consultados por claves foráneas, participan en transacciones financieras o requieren integridad referencial matemática estricta.
  • Usa Columnas JSONB cuando:
    Los atributos son altamente dinámicos o heterogéneos (ej. formularios médicos que cambian según la especialidad, logs de auditoría o configuraciones de usuario variables).
